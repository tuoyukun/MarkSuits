# 格式：design-qa.md

由 designer 在集成态验收时写（coder-impl 之后、tester 之前）。引擎读结果锚点：需要设计验收的
工单，在最新锚点为 `passed` 之前，`mark set <id> testing` 会被拒绝。

```markdown
# <编号> · 设计验收
<!-- mark:qa-round 1 -->

## 环境
<用的入口，取自 handoff.md>

## 状态比对
| S-N | 真实应用中到得了 | 与预览一致 | 备注 |
|---|---|---|---|
| S-1 | 是 | 是 | |
| S-2 | 是 | 否 → D-1 | |
| S-3 | 到不了 | — | 该状态没有入口 |

## UI 层已修
- S-4：<组件哪里有问题、你改了什么>

## 交给 coder-impl 的缺陷
### D-1 · <简短标题>
- 状态：S-2
- 看到：<真实应用的表现>
- 期望：<设计的规定>
- 原因：<容器里的什么导致：装配、数据、时序、外层 CSS……>

## 观察项
| 观察 | 归谁的写域 | 是否本单引入 |
|---|---|---|

## 结论
<!-- mark:qa passed -->
```

规则：

- 比对覆盖 `design.md` 的每一个 `S-N`，一行一个。「到不了」是发现，不是跳过。
- 原因在 UI 层的，你自己修，列在「UI 层已修」，不编号。原因在容器层的，记为 `D-N` 交给
  coder-impl，你不动手。只有未解决的缺陷带 `D-N` 编号：orchestrator 会把本文件里所有 `D-N`
  交给 coder-impl。
- 有任何 `D-N` 就是 `<!-- mark:qa blocked -->`。结果锚点只有一个。
- 后续轮次按该轮重写本文件（`mark:qa-round 2`）。上一轮之后已解决的缺陷不再重复（git 保留历史）；
  新缺陷从上一轮最大的 `D-N` 往后编，编号永不复用。没有任何改动可能影响到的状态可以标「未复核
  （无改动）」；第 1 轮不得使用。
- 两轮都 blocked 后不再迭代：交由人决定。
