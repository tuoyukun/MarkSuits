# 格式：handoff.md

由 coder-impl 写；designer（设计验收）和 tester 读。

```markdown
# <编号> · 交接

## 概要
<按任务（T-N）或修复项说明实现了什么>

## 验收自检表
<!-- mark:ac-table -->
| AC | 判定 | 证据 |
|---|---|---|
| AC-1 | 已实现 | src/projects.test.js::summary |
| AC-2 | 已实现 | frontend/src/pages/Project.tsx（端到端） |
| AC-3 | 未实现 | 见阻塞说明 |

## 状态
| S-N | 在真实应用中从哪里到达 |
|---|---|

## 如何验收
- 启动：<CLAUDE.md 里的命令>
- 入口：<能直接打开的 URL / 路由 / 账号 / 种子数据>

## 修复记录
- <触发源编号（FAIL-N / D-N / R-N）> · <改了什么>

## 带掉修复
- 无

## 阻塞说明
<!-- mark:blocked -->
- 无
```

规则：

- 判定只有 `已实现` 或 `未实现`。
- 证据若是测试文件，该文件必须存在。
- 每条 `未实现` 都在「阻塞说明」里有对应条目：缺什么、卡住哪条 `AC-N`、为什么在方案内做不了。
- 工单有 `design.md` 时必须有「状态」表；有 UI 改动时必须有「如何验收」。
