# 格式：requirement.md

开单前由 orchestrator 和人一起写定；对所有角色只读。放在 main 上的工单目录里。

```markdown
# <编号> · <标题>

## 目标
<一段话：谁需要什么、为什么>

## 用户故事
- US-1：作为<用户>，我想要<动作>，以便<结果>。

## 验收标准
<!-- mark:ac -->
- AC-1：<关于可观察行为、可判定真假的陈述>
- AC-2：……

## 不做
- <本单有意不做的事>

## 依赖
- <依赖的库、服务或其他工单，没有写「无」>

## 待确认
<!-- mark:open-questions -->
- 无
```

规则：

- 每条 `AC-N` 都能被一个没写它的人判定真假。
- `AC-N` 写用户或调用方能观察到的行为。「有一个覆盖 X 的端到端测试」不是验收标准：tester 本来就会
  为每条标准写端到端测试。
- 编号永不复用、不重排；删掉的标准保留并划掉，注明理由。
